Methodology

Data Sources: All data from direct BSC RPC calls (bsc-dataseed1.binance.org, bnb.api.onfinality.io). No secondary sources relied on for on-chain facts.

Methods: eth_getTransactionByHash for decoding function calls; eth_call (0x70a08231) for balanceOf; eth_getStorageAt with ERC1967 slot (0x360894a...) for proxy implementations; eth_getBlockByNumber with full transaction objects for block scanning.

Block Mapping: Dates confirmed via binary search of block timestamps. Oct 1, 2025 = block 63,036,985. Aug 16, 2025 = block 57,840,341.

Pool Type Identification: All 8 pool contract types confirmed via eth_getCode bytecode retrieval + ASCII string extraction. Implementation bytecodes contain pool name strings: 0x5cf081d1 → "CreaterPlayerNodesPool", 0xc062eb45 → "CommunityPool". Pools sharing the same implementation address are confirmed same type. Previously-unknown pools A/B/C/D/E are now fully labeled.

Full-History Pool Scans: All pool outflow data (InvestorsPool, T&A1, CN1/2/3, KOL, CommunityPool) was obtained via sequential full-history Transfer event scans covering blocks 57,840,000–101,400,000 (Aug 2025–May 2026) using OnFinality BNB endpoint (100k block ranges). Each scan is followed by a reconciliation gate: captured outflows vs. (initial_allocation − current balanceOf). A gap >0.5% means INCOMPLETE and triggers a re-scan. Only pools passing the gate are marked final.

Limitations: Exact source of AKE for W2/W4 balances not fully traced (multiple incoming token transfers, requires archival tracing). KOL Pool individual wallet analysis covers all recipients captured by the full-history scan; micro-grants below $1K receive-time value are grouped, not individually analyzed.
